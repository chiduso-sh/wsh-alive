# WSH Alive — Project File Reference

Every single file in this project explained. Useful for onboarding, interviews, or just remembering what you built.

---

## Root Level

### `package.json`
The project manifest. Lists every dependency (Next.js, Tailwind, gray-matter, next-mdx-remote, resend, etc.) and the npm scripts. The `dev` script runs `next dev --webpack` instead of the default Turbopack, because Turbopack had a bug where new API routes weren't being discovered in dev mode.

### `package-lock.json`
Auto-generated by npm. Locks every dependency to an exact version so installs are reproducible. Never edit this manually — npm manages it.

### `tsconfig.json`
TypeScript configuration. Sets up path aliases (`@/*` maps to the project root), enables JSX for React, and configures strict type checking. The `@/` alias is why you can write `import PostCard from "@/components/PostCard"` instead of a relative path.

### `next.config.ts`
Next.js configuration file. Currently minimal — just exports an empty config object. Was temporarily used to add `transpilePackages` for the EngageAI SDK before we switched to a direct API approach.

### `postcss.config.mjs`
PostCSS configuration. Tells the build system to use `@tailwindcss/postcss` as the CSS processor. This is how Tailwind v4 compiles utility classes into real CSS.

### `eslint.config.mjs`
ESLint configuration. Uses `eslint-config-next` which enforces Next.js-specific linting rules (no `<img>` tags, correct use of `next/link`, etc.).

### `next-env.d.ts`
Auto-generated by Next.js. Adds TypeScript type definitions for Next.js-specific things like `next/image` and `next/link`. Never edit or delete this.

### `.env.local`
Environment variables for local development. Contains:
- `ENGAGEAI_API_KEY` — your EngageAI API key (server-only)
- `RESEND_API_KEY` — for newsletter emails (not yet active)
- `RESEND_AUDIENCE_ID` — for Resend contact lists

`NEXT_PUBLIC_` prefix means the variable is exposed to the browser. Never put secrets in `NEXT_PUBLIC_` variables. This file is in `.gitignore` and never pushed to GitHub.

### `.gitignore`
Tells Git which files to ignore. Excludes `node_modules/`, `.next/`, `.env.local`, and build artifacts. Without this, you'd accidentally push hundreds of megabytes of dependencies to GitHub.

### `README.md`
Project documentation. Covers setup, environment variables, project structure, how to write posts, how the EngageAI functions work, and how to deploy to Vercel.

### `AGENTS.md` / `CLAUDE.md`
AI assistant config files. Generated by AI tools during development. Safe to delete — they have no effect on the app.

## `app/` — Next.js App Router

This is the core of the application. Every file in here either becomes a page, an API endpoint, or a configuration that Next.js reads automatically.

### `app/layout.tsx`
The **root layout** — wraps every single page on the site. It:
- Sets global metadata (title, description, Open Graph tags for social sharing, favicon)
- Imports `globals.css` so Tailwind and fonts load everywhere
- Renders `<Navbar />`, `<main>{children}</main>`, `<Footer />`
- Mounts `<EngageAIWidget />` (invisible, initialises the AI SDK)
- Mounts `<EngageAIChat />` (the floating chat button and window)

Any component placed here appears on every page.

### `app/page.tsx`
The **homepage** (`/`). A server component that:
1. Calls `getAllPosts()` at build time to get all blog posts
2. Takes the first post as the featured article, next two as secondary
3. Renders: Hero section → CategoryBar → Featured grid → NewsletterForm

The hero contains the "Move well. Eat well. Live rooted." headline and the hand-drawn SVG tree illustration.

### `app/globals.css`
Global stylesheet loaded by `layout.tsx`. Contains:
- `@import` for Google Fonts (Playfair Display + Jost) — must come before `@import "tailwindcss"`
- `@import "tailwindcss"` — activates Tailwind
- `@theme` block — defines custom colour tokens (`--color-sage`, `--color-earth`, `--color-bark`, etc.) that become Tailwind utility classes like `bg-sage`, `text-earth`
- `.prose` styles — hand-written CSS for blog post content (headings, paragraphs, links, code blocks, blockquotes). Replaces `@tailwindcss/typography` which caused a Turbopack build error.

### `app/not-found.tsx`
The **custom 404 page**. Shows a large "404", a friendly message ("This page has wandered off the trail."), and a button back to home. Automatically rendered by Next.js whenever a route doesn't exist.

### `app/favicon.svg`
The tab icon — a sage green rounded square with a leaf illustration drawn in SVG. Referenced in `layout.tsx`'s metadata `icons` field. Also copied to `public/favicon.svg` so it's served as a static file.

### `app/sitemap.ts`
Auto-generates `sitemap.xml` at build time. Lists every static route (homepage, blog, category pages, about) and every blog post with its last-modified date and priority. Google uses this to crawl and index the site. The base URL is `https://wshalive.com`.

### `app/robots.ts`
Auto-generates `robots.txt`. Tells search engine crawlers to index everything except `/api/` routes (which are server-side only and shouldn't be indexed).

## `app/blog/`

### `app/blog/page.tsx`
The **blog listing page** (`/blog`). Server component that fetches all posts and renders them in a responsive 3-column grid using `PostCard`. Sets the page `<title>` to "All Articles | WSH Alive".

### `app/blog/[slug]/page.tsx`
The **individual blog post page** (`/blog/slow-movement-approach`, etc.). A dynamic route where `[slug]` matches any post filename. It:
- Uses `generateStaticParams()` to pre-render all posts at build time (static generation)
- Uses `generateMetadata()` to set the post's title and Open Graph description dynamically
- Reads the post's MDX content using `getPostBySlug()`
- Renders the content using `<MDXRemote />` from `next-mdx-remote/rsc` which properly handles headings, bold, lists, links, and code blocks
- Shows a category badge, the post title, excerpt, date, and read time in the header

## `app/api/` — API Routes

These run on the server, not the browser. They handle data fetching, external service calls, and proxying.

### `app/api/engageai/route.ts`
The **EngageAI proxy** — the most architecturally important API route. 

**Why it exists:** The EngageAI server at `engageai-sdk-production.up.railway.app` blocks direct browser requests with CORS headers. Browsers enforce CORS; servers don't. So instead of the browser calling EngageAI directly, it calls this route, which forwards the request from the server to EngageAI.

**How it works:** Receives `{ path, body }` from the browser, forwards a POST request to `${ENGAGE_SERVER}${path}` with the `X-EngageAI-Key` authentication header, and returns EngageAI's response. Also logs all requests and responses to the terminal for debugging.

### `app/api/posts/route.ts`
A **GET endpoint** that returns blog posts as JSON. Supports an optional `?category=workouts` query parameter for filtering. This is what the EngageAI assistant calls when a user asks "show me workout articles" — the AI can't read the filesystem directly, so it uses this API.

### `app/api/subscribe/route.ts`
A **POST endpoint** for newsletter signups. Receives `{ name, email }`, validates they're both present, and (in production) would call Resend to add the contact to a mailing list. The Resend integration is commented out and ready to activate — just add your `RESEND_API_KEY` and `RESEND_AUDIENCE_ID` to `.env.local` and uncomment the code.

## `components/`

Reusable UI components used across multiple pages.

### `components/Navbar.tsx`
**Client component** (`"use client"`). The sticky top navigation bar. Contains:
- The WSH Alive logo linking to `/`
- Desktop nav links (Workouts, Nutrition, Lifestyle, About)
- A Subscribe button linking to `/subscribe`
- A hamburger menu for mobile that toggles a dropdown with the same links
- Uses `useState` to track whether the mobile menu is open

### `components/Footer.tsx`
**Server component**. Simple footer with the logo, nav links (About, Privacy, Contact, Instagram), and copyright year. Uses `new Date().getFullYear()` so the year always updates automatically.

### `components/PostCard.tsx`
**Client component**. A reusable card that displays a single blog post. Props:
- `post` — the post metadata (title, excerpt, category, date, readTime, optional coverImage)
- `large` — boolean that makes the card taller with the excerpt visible (used for the featured post)

Shows a coloured placeholder if no `coverImage` is provided (most posts don't have one yet). The category gets a colour-coded tag (sage for workouts, earth for nutrition, blue for lifestyle, purple for mindfulness). Hover lifts the card with a CSS transform.

### `components/CategoryBar.tsx`
**Client component**. The horizontal bar of four category links below the hero. Each link is a coloured circle + label + article count. On mobile it collapses to a 2×2 grid. Hover highlights the row with the sage-pale background colour.

### `components/NewsletterForm.tsx`
**Client component**. The newsletter signup section with name + email inputs and a submit button. Manages its own state (`name`, `email`, `status`). On submit it calls `POST /api/subscribe`. Shows a success state ("You're in! See you Sunday.") on success and an error message on failure. The `status` can be `idle`, `loading`, `success`, or `error`.

### `components/EngageAIWidget.tsx`
**Client component** — the brain of the AI integration. Invisible on screen (returns `null`). On mount it:

1. Creates an `EngageAIClient` instance with a unique session ID
2. Registers 4 functions the AI can call:
   - `get_all_posts` — fetches all posts and pushes a formatted list into the chat
   - `get_posts_by_category` — fetches filtered posts and pushes them into the chat; tracks `lastCategoryShown` so "yes" can navigate without re-asking the AI
   - `navigate_to` — calls `router.push()` to change the page
   - `subscribe_user` — calls `POST /api/subscribe`
3. Sends the manifest to EngageAI via the proxy (`POST /api/v1/register`)
4. Exposes the client instance via `getEngageAIClient()` so `EngageAIChat` can call `sendMessage()`

The `_handleAction()` method handles the function-call loop: when EngageAI responds with a `function_call` action type, the client executes the registered handler, sends results back to EngageAI via `/api/v1/results`, and recursively processes the follow-up response.

### `components/EngageAIChat.tsx`
**Client component** — the visible AI chat UI. A floating 🌿 button fixed to the bottom-right of every page. When clicked, it opens a chat window with:
- A sage-green header ("WSH Alive Guide")
- A scrollable message list with user messages (right, sage) and AI messages (left, cream)
- An animated typing indicator (3 bouncing dots) while waiting for a response
- A text input + send button at the bottom
- `whitespace-pre-wrap` on messages so the formatted post listings render with line breaks

Also exports `pushAIMessage()` — a global function that `EngageAIWidget` calls to inject AI messages directly into the chat (bypassing the AI's response for data-heavy replies like post listings).

Intercepts affirmative replies ("yes", "sure", "take me there", etc.) locally when a category was just shown, navigating via `window.location.href` instead of re-querying the AI.

## `lib/`

Utility functions used by server components and API routes.

### `lib/posts.ts`
**Server-only**. Uses Node.js `fs` to read `.md` and `.mdx` files from `content/posts/`. Exports two functions:
- `getAllPosts(categoryFilter?)` — reads all posts, parses frontmatter with `gray-matter`, optionally filters by category, and sorts by date descending
- `getPostBySlug(slug)` — finds a single post file by slug, returns both the metadata and the raw MDX content string

### `lib/posts-client.ts`
**Client-safe version**. Can't use `fs` in the browser, so this version fetches from `/api/posts` instead. Currently used as a utility reference — the actual browser-side fetching happens inside `EngageAIWidget.tsx`'s function handlers.

## `content/posts/`

The blog content. Each file is a Markdown file with frontmatter at the top. The filename (minus extension) becomes the URL slug.

### `content/posts/slow-movement-approach.md`
Post about low-intensity training and why it outperforms high-impact routines long-term. Category: `workouts`. URL: `/blog/slow-movement-approach`.

### `content/posts/whole-foods-muscle-repair.md`
Post about five foods that aid overnight muscle recovery. Category: `nutrition`. URL: `/blog/whole-foods-muscle-repair`.

### `content/posts/morning-stillness-ritual.md`
Post about a 10-minute morning routine for calm and intention. Category: `lifestyle`. URL: `/blog/morning-stillness-ritual`.

**To add a new post**, create a new `.md` file here with this structure:
```markdown
---
title: "Your Post Title"
excerpt: "One sentence summary."
category: workouts
date: "2026-05-01"
readTime: "5 min read"
---

Your content here...
```

## Architecture Summary

```
Browser
  │
  ├── Loads page (SSR/SSG from Next.js)
  │
  ├── EngageAIWidget mounts → registers functions → POST /api/engageai (proxy)
  │                                                       │
  │                                                       └── → EngageAI server
  │
  ├── User types in EngageAIChat → POST /api/engageai
  │                                       │
  │                                       └── EngageAI decides action:
  │                                           ├── respond → text reply shown in chat
  │                                           └── function_call → handler runs:
  │                                               ├── get_all_posts → GET /api/posts
  │                                               ├── get_posts_by_category → GET /api/posts?category=x
  │                                               ├── navigate_to → router.push()
  │                                               └── subscribe_user → POST /api/subscribe
  │
  └── Results sent back to EngageAI → final reply shown in chat
```
